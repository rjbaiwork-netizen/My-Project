# My-Project AI Provider Router

The AI Provider Router is the single AI gateway for generation and embeddings.

## Routing

Requests are grouped into three purposes: knowledge (knowledge ingestion, semantic search and memory embeddings), agent (agent/chain generation), and production (user-facing chat and production generation).

`AI_PROVIDER_ORDER` defines the preferred failover order. Providers without a configured API key are ignored.

## Built-in providers

- OpenAI: existing purpose-specific routing
- Google Gemini: generation + embeddings + multimodal capability
- Groq: OpenAI-compatible generation fallback
- Mistral: OpenAI-compatible generation + embeddings

Additional OpenAI-compatible providers can be added with `AI_PROVIDER_REGISTRY_JSON` without changing application business logic.

## Failover

A provider failure is logged to `AIProviderEvent`. Transient failures such as 429, 5xx, timeouts and network failures temporarily enter a short circuit-breaker cooldown. The router immediately tries the next compatible configured provider.

The frontend never receives API credentials or provider secrets.

## RAG compatibility

Embeddings are tagged with `embeddingProvider`. Retrieval only compares vectors generated by the same provider. Therefore changing the active embedding provider does not corrupt existing vectors. Reindexing is available from the Provider Router UI after switching the preferred embedding provider.

## Free-tier rule

Provider configuration is capability-based, not provider-name-based. A provider should be enabled for production only when its current free-tier/API terms, model availability and rate limits have been verified. Free-tier availability can change independently of this repository.
